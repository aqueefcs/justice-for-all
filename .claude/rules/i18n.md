# i18n

- UI strings: i18next with JSON namespaces in `packages/i18n/locales/<lang>/<namespace>.json` (`common`, `home`, `library`, `guides`, `templates`, `errors`, `admin`).
- Always use `t('namespace:key')`. Keys are semantic (`guides.fir.startButton`), not English sentences.
- When adding a key: add it to `en`, and add a placeholder to every other existing locale (same English text, prefixed `[TODO]`). CI fails on missing keys.
- Locales supported now: `en`. Scaffolded: `hi`. Planned: regional languages chosen by the team. Use BCP-47 codes.
- No string concatenation for sentences; use interpolation (`t('x', { count })`) and plurals.
- Format numbers, currency (₹) and dates with `Intl` for the active locale; show dates in IST.
- Make sure fonts render Devanagari and other Indic scripts (Noto Sans family). Test with long strings, because Hindi is often longer than English.
- Content (acts, guides, templates) is not in i18n JSON. It lives in DB `translations` and content packs. Machine translation (Bhashini/IndicTrans2) produces a `draft` only, and a lawyer must review it before it can be published.
